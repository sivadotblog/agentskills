## Resolution

Each false positive is accepted in a SkillSpector baseline under [baselines/](baselines/), one file per flagged skill, with the reason recorded. The baselines use exact fingerprints rather than glob rules. If the skill text changes or SkillSpector is upgraded, the finding comes back for another review. Rewording upstream's skills just to silence the scanner would make updating from Spec Kit harder.

With the baselines applied, every skill scores **0/100, SAFE, 0 new findings** (5 suppressed: checklist 1, implement 3, specify 1).

## Findings

### 1. PE3 Credential Access, HIGH: `speckit-implement/SKILL.md:119` (`.npmrc`)
> Check if .npmrc or package.json exists → create/verify .npmignore (if publishing)

**Assessment: false positive.** The skill only checks whether `.npmrc` exists, to decide whether to create a `.npmignore`. It never reads the file's contents.

### 2. PE3 Credential Access, HIGH: `speckit-implement/SKILL.md:147` (`secret.yaml`)
### 3. PE3 Credential Access, HIGH: `speckit-implement/SKILL.md:147` (`kubeconfig`)
> **Kubernetes/k8s**: `*.secret.yaml`, `secrets/`, `.kube/`, `kubeconfig*`, `*.key`, `*.crt`

**Assessment: false positive.** This line lists patterns to *add to ignore files*, so secrets stay out of version control and builds. That protects credentials rather than reading them.

### 4. EA2 Autonomous Decision Making, MEDIUM: `speckit-checklist/SKILL.md:118`
> Never ask the user to restate what they already said

**Assessment: false positive.** This is a rule about how to phrase questions, not a way to bypass confirmation. The same section tells the agent to ask the user when unsure.

### 5. EA2 Autonomous Decision Making, MEDIUM: `speckit-specify/SKILL.md:60`
> Do not ask the user to repeat it unless they provided an empty command.

**Assessment: false positive.** This only stops the agent asking for the feature description twice. No high-impact action is taken without the user.

## Things to watch (not flagged by the scanner)

- **`speckit-implement` writes code and runs commands.** It is the only skill that makes large changes to a repo. Run it on a branch and review the diff.
- **`speckit-taskstoissues` creates GitHub issues.** This changes something outside your machine. It uses the GitHub MCP server, only proceeds if `origin` is a GitHub URL, and creates issues only in that repo. Upstream marks it deprecated in favour of the `github` extension (`/speckit-github-taskstoissues`).
- **Extension hooks:** every skill reads `.specify/extensions.yml` and may tell the agent to run hook commands from it, some marked mandatory. Treat that file as trusted code, and review any Spec Kit extension before installing it.
- **Project scripts:** the skills run `.specify/scripts/bash/*.sh` from your repo. These come from `specify init`, not from this plugin. A separate SkillSpector scan of the generated `.specify/` folder scored 14/100 (LOW). Its only findings were 10 AS3 "Skill Enumeration" hits on `integrations/claude.manifest.json`, which simply lists the installed skill files: also false positives.
- **Static scan only:** the LLM semantic pass was not run. Re-run with an LLM provider set up (see the SkillSpector README) for a deeper check.

## Re-run
```
uv tool install git+https://github.com/NVIDIA/skillspector.git
plugins/speckit/review/scan.sh   # per-skill scan with baselines; exits 1 on any new finding
```
SkillSpector refuses `--baseline` on recursive multi-skill scans, so `scan.sh` scans each skill on its own. To regenerate the unsuppressed full report:
```
skillspector scan plugins/speckit/skills --recursive --no-llm --format markdown --output plugins/speckit/review/skillspector-report.md
```
After updating the skills from Spec Kit, re-review any finding that comes back, then regenerate that skill's baseline with `skillspector baseline plugins/speckit/skills/<skill> --no-llm -o plugins/speckit/review/baselines/<skill>.yaml` and write the reasons again.
